数据流全景

从浏览器到 app-server 的四条主链路。

阅读约 10 分钟 第 17 / 27 篇 源自 docs/ARCHITECTURE.md · docs/API.md

四条主链路

codex-chat-mobile 有四条主数据流，覆盖核心业务场景。

链路一：发消息

sequenceDiagram participant B as 浏览器 participant S as server.js participant A as agent-appserver.js participant C as codex app-server B->>S: user:message {text, attachments} S->>S: 校验附件 S->>S: 路由到实例 S->>A: send(text) A->>A: 检查状态 alt turn 运行中且可 steer A->>C: turn/steer {input} else 空闲 A->>C: turn/start {input, model, cwd} end C-->>A: turn/started (notification) loop 流式响应 C-->>A: item/agentMessage/delta {text} A->>A: 映射为 agent:event A-->>S: emit('agent:event', envelope) S-->>B: Socket.IO 广播 end C-->>A: turn/completed {status} A->>A: busy = false A-->>S: emit('agent:event', {type:'result'}) S-->>B: 广播完成

链路二：审批

sequenceDiagram participant C as codex app-server participant A as agent-appserver.js participant AB as ApprovalBroker participant S as server.js participant B as 浏览器 C->>A: S→C 审批请求 A->>AB: handleRequest(rpcId, method, params) AB->>AB: 分类：command/file/permission/userInput AB->>S: emit('approval_request', payload) S->>B: Socket.IO 广播 S->>S: Web Push 通知（如果配置） Note right of AB: turn 挂起等待 B->>S: user:approval {approvalId, decision} S->>AB: resolve(approvalId, result) AB->>A: respond(rpcId, result) A->>C: JSON-RPC response AB->>S: emit('approval_revoked') S->>B: 广播撤销（通知他端）

链路三：断线恢复

sequenceDiagram participant B as 浏览器 participant S as server.js B->>B: 断线 B->>B: 重连 B->>S: catch-up {sessionId, lastSeq} S->>S: 从重放缓冲查找 S->>S: 增量补发 lastSeq 之后的事件 S-->>B: 补发错过的事件 B->>B: 渲染补发的事件

链路四：文件上传

sequenceDiagram participant B as 浏览器 participant S as server.js participant U as uploads.js participant FS as 文件系统 participant A as agent-appserver.js participant C as codex app-server B->>S: user:message {attachments} S->>U: validateAttachments(attachments) U->>U: 校验类型、大小、数量 U->>FS: saveAttachments(files) FS-->>U: 文件路径 U-->>S: 绝对路径列表 S->>A: turn/start {input, attachments: [路径]} A->>A: 注入提示词 A->>C: JSON-RPC request C->>C: 读取文件 C-->>A: 流式响应

背压处理

当 app-server 返回 -32001 "Server overloaded" 时：

graph LR A[发送请求] --> B[收到 -32001] B --> C[指数退避] C --> D[重试] D --> E{成功?} E -->|是| F[继续] E -->|否| G[达到上限?] G -->|否| C G -->|是| H[报错]

重放缓冲

环形缓冲区

  • 容量：BUFFER_CAP（默认 500）
  • 淘汰：FIFO
  • 索引：自增 seq
