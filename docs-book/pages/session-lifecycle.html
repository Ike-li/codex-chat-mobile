会话生命周期

initialize → thread → turn 的完整流程。

阅读约 14 分钟 第 12 / 27 篇 源自 agent-appserver.js

会话生命周期总览

会话生命周期是 codex-chat-mobile 的核心流程：从创建到销毁，经历 initialize → thread → turn 三个阶段。

stateDiagram-v2 [*] --> Spawning: 创建实例 Spawning --> Initializing: spawnIfNeeded Initializing --> Ready: initialize + initialized Ready --> TurnActive: turn/start TurnActive --> Ready: turn/completed Ready --> Archived: thread/archive Archived --> Ready: thread/unarchive Ready --> Deleted: thread/delete Ready --> [*]: dispose

阶段一：初始化

spawnIfNeeded

当第一个消息到达时，触发子进程启动：

sequenceDiagram participant S as server.js participant A as agent-appserver.js participant C as codex app-server S->>A: send(text) A->>A: spawnIfNeeded() A->>C: spawn('codex', ['app-server']) A->>A: 设置 stdin/stdout 监听 A->>A: 启动 idle timer

initialize

子进程启动后，发送 initialize 请求：

sequenceDiagram participant A as agent-appserver.js participant C as codex app-server A->>C: initialize {clientInfo, capabilities} C-->>A: result {serverInfo} C-->>A: initialized (notification) A->>A: 标记 initialized = true

thread/start 或 thread/resume

初始化完成后，创建或恢复线程：

sequenceDiagram participant A as agent-appserver.js participant C as codex app-server alt 新会话 A->>C: thread/start {cwd} C-->>A: result {threadId} else 恢复会话 A->>C: thread/resume {threadId} C-->>A: result {thread} end A->>A: 设置 sessionId = threadId

阶段二：Turn 生命周期

turn/start

用户发送消息时，启动 turn：

sequenceDiagram participant B as 浏览器 participant S as server.js participant A as agent-appserver.js participant C as codex app-server B->>S: user:message {text} S->>A: send(text) A->>A: 检查状态 alt turn 运行中且可 steer A->>C: turn/steer {input} else 空闲 A->>C: turn/start {input, model, cwd} end C-->>A: turn/started (notification)

流式响应

turn 运行中，app-server 发来流式通知：

sequenceDiagram participant A as agent-appserver.js participant C as codex app-server loop 流式响应 C-->>A: item/started {item} C-->>A: item/agentMessage/delta {text} C-->>A: item/reasoning/textDelta {text} C-->>A: item/commandExecution/outputDelta {text} C-->>A: item/completed {item} end C-->>A: turn/completed {status} A->>A: busy = false

turn/steer

turn 运行中，用户发送新输入：

sequenceDiagram participant B as 浏览器 participant S as server.js participant A as agent-appserver.js participant C as codex app-server B->>S: user:message {text} S->>A: send(text) A->>A: 检查状态：turn 运行中 A->>C: turn/steer {input} C-->>A: 继续流式响应

输入队列

turn 运行中且不可 steer 时，输入进入队列：

stateDiagram-v2 [*] --> Idle: 空闲 Idle --> TurnActive: turn/start TurnActive --> Queued: 输入到达（不可 steer） Queued --> TurnActive: turn/completed 后 drain TurnActive --> Idle: turn/completed

阶段三：审批

审批请求

app-server 发来审批请求时：

sequenceDiagram participant C as codex app-server participant A as agent-appserver.js participant B as 浏览器 C->>A: S→C 审批请求 A->>A: ApprovalBroker.handleRequest A->>A: 分类：command/file/permission/userInput A->>B: approval_request 信封 Note right of A: turn 挂起等待

审批决议

用户在浏览器上批准或拒绝：

sequenceDiagram participant B as 浏览器 participant A as agent-appserver.js participant C as codex app-server B->>A: user:approval {decision} A->>A: ApprovalBroker.resolve A->>C: JSON-RPC response A->>B: approval_revoked 信封（通知他端） Note left of A: turn 继续执行

阶段四：销毁

dispose

实例销毁时：

  1. 标记 disposed：防止后续操作
  2. 清理队列：清空输入队列
  3. 清理审批：清空 pending 审批
  4. 清理重试：清空背压重试
  5. 关闭子进程：stdin.end()
  6. 清理定时器：clearInterval(idleTimer)

空闲回收

超过 IDLE_TIMEOUT_MS 未活动时：

graph LR A[checkIdle] --> B{超时?} B -->|是| C[dispose] B -->|否| D[继续]

状态模型

会话状态

状态 含义
idle 空闲，可接受新 turn
busy turn 运行中
approval_requested 等待审批
process_exit 子进程退出
process_error 子进程错误

实例状态

状态 含义
spawning 正在启动子进程
initializing 正在初始化
ready 就绪
disposed 已销毁
