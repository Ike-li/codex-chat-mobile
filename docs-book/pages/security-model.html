安全模型

AUTH_TOKEN、设备信任、loopback 规则。

阅读约 10 分钟 第 22 / 27 篇 源自 SECURITY.md · docs/ARCHITECTURE.md

安全模型概述

codex-chat-mobile 是控制真实开发机器的本地控制面，安全是核心设计约束。

安全原则
无托管后端：浏览器直连本机，不经过任何云服务
AUTH_TOKEN 为空 → loopback-only：任何非本机部署必须设置 token
审批不自动决议：安全默认
owner-only 权限：本地状态只保存在本机

鉴权体系

AUTH_TOKEN

graph TD A[连接] --> B{AUTH_TOKEN?} B -->|空| C{loopback?} C -->|是| D[允许] C -->|否| E[拒绝] B -->|非空| F{token 正确?} F -->|是| D F -->|否| E
  • 空：仅允许 loopback host 和 loopback socket
  • 非空：允许非 loopback，timing-safe 比较

timing-safe 比较

防止时序攻击：

实现
使用 crypto.timingSafeEqual 比较 token，防止通过响应时间猜测 token。

设备信任

stateDiagram-v2 [*] --> Pending: 新设备连接 Pending --> Trusted: 已信任设备批准 Pending --> Denied: 已信任设备拒绝 Trusted --> [*]: 允许 Denied --> [*]: 拒绝
  • 新设备：可能需已信任设备批准
  • 已信任设备：可批准或拒绝新设备
  • 存储：owner-only 文件

文件安全

上传校验

检查 说明
类型校验 MIME 类型白名单
大小限制 单文件 10MB，总 50MB
数量限制 最多 10 个文件
symlink 防御 拒绝符号链接

owner-only 落盘

  • 权限：0o600
  • 函数：writeOwnerOnlyFile
  • 应用：上传文件、审计日志、设备信任

日志安全

路径脱敏

函数
sanitizePath：移除用户主目录等敏感路径

token 脱敏

函数
maskToken：只显示前 4 位 + ****

敏感字段过滤

RPC 日志中过滤：

  • token、secret、password
  • authorization、api_key
  • private_key、refreshToken
  • dataBase64

CSP 与 Frame 保护

Content Security Policy

  • default-src：'self'
  • script-src：'self'
  • style-src：'self' 'unsafe-inline'
  • connect-src：'self' ws: wss:

Frame 保护

  • X-Frame-Options：DENY
  • frame-ancestors：'none'

Admin 门控

解锁流程

sequenceDiagram participant B as 浏览器 participant S as server.js B->>S: admin:unlock {confirmText: "ENABLE ADMIN"} S->>S: 验证短语 S->>B: {ok:true, adminMode:true}

逐操作确认

  • adminConfirm：必须等于 action 名
  • 审计日志：owner-only

Labs 门控

环境变量

  • CODEX_P3_EXPERIMENTAL：1 启用

初始化声明

  • experimentalApi：true

威胁模型

假设

  • 开发机可信：本机安全
  • 网络不可信：局域网/互联网可能被监听
  • 浏览器可信：用户设备安全

威胁

威胁 缓解
未授权访问 AUTH_TOKEN + 设备信任
中间人攻击 HTTPS（推荐 Tailscale）
时序攻击 timing-safe 比较
符号链接攻击 symlink 防御
日志泄露 路径/token 脱敏
恶意操作 审批不自动决议

部署安全

本地部署

  • loopback-only：默认安全
  • 无需 token：本机访问

远程部署

  • 必须 HTTPS：PWA/Push 要求
  • 必须 AUTH_TOKEN：非 loopback 要求
  • 推荐 Tailscale：零配置 HTTPS

漏洞披露

见 SECURITY.md。
