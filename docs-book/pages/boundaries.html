职责边界与生态

各模块如何分工，不可逾越的职责铁律。

阅读约 8 分钟 第 5 / 27 篇 源自 docs/ARCHITECTURE.md · SECURITY.md

模块分工

codex-chat-mobile 由四个核心模块组成，每个模块职责清晰，不越界。

各模块职责

模块 文件 职责 不做什么
HTTP/Socket 网关 server.js 鉴权、路由、实例生命周期、广播、catch-up 不直接调用 Codex CLI
JSON-RPC 桥 agent-appserver.js 协议生命周期、事件映射、队列、中断 不处理 HTTP/Socket 细节
前端 SPA public/index.html + public/js/app.js UI 渲染、交互、PWA 不持有业务逻辑
审批代理 approval-broker.js 审批分类、决议、撤销 不处理其他协议消息
文件上传 uploads.js 校验、限量、owner-only 落盘 不处理协议帧
历史读取 history.js 读取 Codex 原生 session JSONL 不写入历史
设备信任 devices.js 设备审批、pending 管理 不处理其他鉴权
状态栏 statusline.js git 状态、context 用量 不处理业务逻辑

依赖方向

依赖规则
  • 单向依赖：server.js → agent-appserver.js → codex app-server
  • 不逆向：agent-appserver.js 不依赖 server.js
  • 支撑模块：被 server.js 或 agent-appserver.js 调用，不互相依赖

职责边界（铁律）

server.js 做什么

  • HTTP 路由和静态托管
  • Socket.IO 事件注册和广播
  • 鉴权（AUTH_TOKEN + 设备信任）
  • 实例生命周期管理
  • 工作目录路由
  • Web Push 通知
  • 断线恢复（catch-up）

server.js 不做什么

  • 不直接调用 Codex CLI
  • 不处理 JSON-RPC 细节
  • 不持有 AI 对话状态
  • 不解析 app-server 通知

agent-appserver.js 做什么

  • JSON-RPC 请求 ID 管理
  • initialize/thread/turn 生命周期
  • app-server 通知映射
  • 审批请求代理
  • 输入队列和中断
  • 背压重试

agent-appserver.js 不做什么

  • 不处理 HTTP/Socket 细节
  • 不管理设备信任
  • 不处理文件上传
  • 不管理 Web Push

与 Codex CLI 的边界

codex-chat-mobile 是 Codex CLI 的 控制面，不是替代品：

职责 归属
AI 对话、模型调用 Codex app-server
工具执行（命令、文件操作） Codex app-server
审批请求生成 Codex app-server
审批决议 codex-chat-mobile（用户通过手机）
UI 渲染 codex-chat-mobile
会话持久化 Codex app-server（thread JSONL）

外部系统集成

上游
Codex CLI（codex app-server，通过 stdio JSON-RPC）
下游
OpenAI API（由 Codex CLI 内部调用，本项目不直接交互）
推送服务
Web Push（VAPID，可选）
认证
ChatGPT Device Code Flow（由 Codex CLI 处理）

不可逾越的铁律

设计约束
  1. app-server 是唯一后端：不使用旧的 codex exec --json
  2. Socket.IO 信封层是前端稳定契约：不随意修改信封格式
  3. 日常回归走 mock：不默认调用真实 Codex CLI
  4. 未知类型降级而非丢弃：未知 item → raw envelope
  5. 审批不自动决议：安全默认
