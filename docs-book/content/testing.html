测试体系概述

codex-chat-mobile 的测试体系分为确定性的本地门禁和可选的真机冒烟检查。

测试原则
mock 驱动：日常开发使用确定性 mock，零 token
四道门禁：每次提交必须通过
验收矩阵：四个维度判断场景

四道门禁

graph LR A[代码变更] --> B[lint] B --> C[test] C --> D[protocol:check] D --> E[test:e2e] E --> F[提交]
门禁 命令 覆盖范围
Lint npm run lint ESLint 规则检查
单元/集成测试 npm test node:test，覆盖单元、集成、协议、安全、UI、文档契约
协议检查 npm run protocol:check 对照 .protocol/stable/ 检查覆盖与漂移
E2E npm run test:e2e Playwright mobile Chrome，连接 mock server

单元测试

  • 纯函数：statusline.js、sanitizer.js、server-security.js
  • 数据处理：normalizeThread、normalizeThreadHistoryMessages
  • 工具函数：maskToken、sanitizePath

集成测试

  • Socket.IO 路由：事件注册、ack、鉴权边界
  • JSON-RPC 生命周期：initialize → thread → turn
  • 审批系统：分类、决议、撤销
  • 文件安全：上传校验、owner-only 落盘

E2E 测试

  • 关键流程：发消息、审批、附件
  • 富事件渲染：命令卡片、reasoning、diff
  • Native 控件：线程列表、模型切换
  • 多实例：标签隔离、工作区切换

验收矩阵

每个产品关键场景都按四个维度判断：

维度 含义
功能等价 移动端获得与终端等效的体验
状态可见 当前状态（busy/idle/error）清晰可见
失败可恢复 断线、崩溃后能恢复
权限可控 审批、权限在用户控制下

手工冒烟清单

只在确定性门禁通过后使用：

编号 场景
TC-1 基础对话能发送提示词并流式显示响应
TC-2 斜杠命令可用
TC-3 停止按钮能中断活跃 turn
TC-4 busy turn 期间的输入会按状态进入队列或 steer
TC-5 审批批准路径会执行
TC-6 审批拒绝路径不会执行
TC-7 文件上传会显示附件元数据
TC-8 状态栏显示 cwd、sandbox、approval policy 等
TC-9 历史抽屉能浏览过去的会话
TC-10 多工作区切换遵守配置
TC-11 多实例标签隔离活跃对话
TC-12 模型控件显示可用模型状态
TC-13 权限控件会更新状态
TC-14 刷新/重连能 catch up
TC-15 失败后复制和 retry 仍可用
TC-16 Web Push 订阅需配置 VAPID
TC-17 PWA manifest 支持 standalone 安装
TC-18 移动端布局保持 composer 控件可见

Mock Server

scripts/mock-codex-app-server.js

  • 确定性：相同输入产生相同输出
  • 零 token：不调用真实 Codex CLI
  • 协议兼容：模拟 app-server 行为

使用场景

  • 日常开发：npm run test:e2e
  • CI：npm run test:ci
  • 回归测试：每次提交

真实 Codex 冒烟

边界
真实 Codex CLI 冒烟测试不属于默认 E2E 路径。只有在验证本地集成、审批或协议升级时才运行。运行时使用一次性工作区，并显式设置 approval policy。
