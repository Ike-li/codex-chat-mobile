审批系统概述

审批系统是 codex-chat-mobile 的安全核心：当 Codex 要执行命令或改文件时，需要用户在手机上批准或拒绝。

安全原则
不自动决议：安全默认，不自动批准也不自动拒绝
必须应答：未应答的审批会让 turn 挂起
显式控制：用户必须显式批准或拒绝

审批类型

类型 方法 触发场景
命令执行 item/commandExecution/requestApproval Codex 要执行 shell 命令
文件变更 item/fileChange/requestApproval Codex 要修改文件
权限请求 item/permissions/requestApproval Codex 请求额外权限
用户输入 item/tool/requestUserInput Codex 需要用户提供信息

审批流程

sequenceDiagram participant C as codex app-server participant AB as ApprovalBroker participant S as server.js participant B as 浏览器 C->>AB: S→C 审批请求 AB->>AB: handleRequest(rpcId, method, params) AB->>AB: 分类：command/file/permission/userInput AB->>S: emit('approval_request', payload) S->>B: Socket.IO 广播 Note right of AB: turn 挂起等待 B->>S: user:approval {approvalId, decision} S->>AB: resolve(approvalId, result) AB->>C: JSON-RPC response AB->>S: emit('approval_revoked') S->>B: 广播撤销（通知他端）

ApprovalBroker

ApprovalBroker 是审批系统的核心类，负责：

  • 分类：按 method 精确分类审批类型
  • 登记：维护 approvalId 到 rpcId 的映射
  • 决议：将用户决议转发给 app-server
  • 撤销：监听 serverRequest/resolved 撤销他端已决弹窗

审批卡片

前端渲染审批卡片：

命令审批卡片

显示将执行的命令，包含批准/拒绝按钮。

  • 批准 → 执行命令
  • 拒绝 → 不执行

文件审批卡片

显示将变更的文件，包含批准/拒绝按钮。

  • 批准 → 应用变更
  • 拒绝 → 不应用

Web Push 通知

审批到达时，可触发 Web Push 通知：

graph LR A[审批到达] --> B{VAPID 配置?} B -->|是| C[发送 Push] B -->|否| D[仅 Socket.IO] C --> E[手机通知]

Push 通知内容：

  • 标题：「Codex 待审批」
  • 正文：命令内容或文件变更摘要

撤销机制

当审批在他端已决时，撤销本地弹窗：

sequenceDiagram participant B1 as 浏览器 1 participant S as server.js participant B2 as 浏览器 2 B1->>S: user:approval {approve} S->>S: 决议 S->>B2: approval_revoked 信封 B2->>B2: 移除审批卡片

Legacy 支持

旧式审批方法保留兜底：

旧方法 新方法
applyPatchApproval item/fileChange/requestApproval
execCommandApproval item/commandExecution/requestApproval

审批策略

通过 CODEX_APPROVAL_POLICY 环境变量配置：

策略 含义
untrusted 所有操作都需要审批
on-failure 失败时需要审批
on-request 默认，按请求审批
granular 细粒度审批
never 从不审批

审计日志

审批决议记录到 owner-only 审计日志：

  • 路径：.codex-chat-approval-audit.jsonl
  • 内容：approvalId、method、decision、timestamp
  • 权限：owner-only
