分层架构

codex-chat-mobile 采用三层架构：浏览器 → Node 网关 → Codex app-server。每层职责清晰，不越界。

各层职责

表现层（public/index.html + public/js/app.js）

  • public/index.html 提供 HTML/CSS shell，public/js/app.js 作为外部 ESM 承载应用交互
  • 渲染：文本增量、reasoning、命令/工具卡片、文件变更、审批
  • 交互：输入框、审批按钮、斜杠命令、附件上传
  • 状态：连接状态、会话状态、实例切换

网关层（server.js）

  • HTTP 路由：静态资源、健康检查、VAPID 公钥
  • Socket.IO 事件：鉴权、路由、ack 统一格式
  • 实例生命周期：agents map 按 instanceId 维护活跃会话
  • 设备信任：新设备需已信任设备批准
  • Web Push：VAPID 推送通知

桥接层（agent-appserver.js）

  • JSON-RPC 2.0：请求 ID 管理、超时、重试
  • 生命周期：initialize → thread → turn
  • 事件映射：app-server 通知 → agent:event 信封
  • 审批代理：ApprovalBroker 分类与决议
  • 队列：输入队列、中断、steer

执行层（codex app-server）

  • AI 对话：模型调用、流式响应
  • 工具执行：命令运行、文件操作
  • 审批请求：命令/文件/权限审批

四条主链路：

1. 发消息

安全边界

安全原则
  • 无托管后端：浏览器直连本机，不经过任何云服务
  • AUTH_TOKEN 为空 → loopback-only：任何非本机部署必须设置 token
  • 审批不自动决议：安全默认，不自动批准也不自动拒绝
  • owner-only 权限：上传文件、审计日志、设备信任都只保存在本机

协议边界

产品依赖 codex app-server，不依赖旧的 codex exec --json 行为。稳定主链路是：

  1. initialize（握手）
  2. initialized（确认）
  3. thread/start 或 thread/resume 或 thread/fork
  4. turn/start 或 turn/steer
  5. 服务端流式通知
  6. turn/completed 或 error 或中断处理

未知 server request 作为协议事件处理，不能静默卡住应用。未知 item type 降级为可见的 raw envelope，而不是直接丢失。
