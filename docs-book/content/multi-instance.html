多实例概述

多实例是 codex-chat-mobile 的隔离能力：每个标签对应一个独立的 app-server 会话实例，互不串流。

核心理念
标签隔离：每个标签独立会话
工作区路由：多工作目录白名单
实例生命周期：空闲回收、崩溃恢复

工作区路由

WORK_DIR

主工作目录，Codex CLI 在此目录下运行：

  • 默认：homedir()
  • 配置：WORK_DIR 环境变量
  • 校验：必须存在且是目录

WORK_DIRS

额外工作目录白名单：

  • 格式：逗号分隔
  • 校验：每个目录必须存在且是目录
  • 去重：与 WORK_DIR 去重

路由逻辑

graph TD A[收到请求] --> B{有 cwd?} B -->|是| C{cwd 在 workDirs?} C -->|是| D[使用 cwd] C -->|否| E[拒绝] B -->|否| F[使用 WORK_DIR]

标签隔离

隔离维度

维度 隔离方式
app-server 子进程 每个实例独立进程
会话状态 独立 thread
输入队列 独立队列
审批状态 独立 pending
重放缓冲 独立缓冲区

广播机制

事件广播到所有连接的客户端：

graph LR A[实例 1 事件] --> B[server.js] C[实例 2 事件] --> B B --> D[io.emit] D --> E[浏览器 1] D --> F[浏览器 2]

客户端通过 instanceId 过滤事件。

空闲回收

检查机制

graph TD A[checkIdle 定时器] --> B{超时?} B -->|是| C[dispose] B -->|否| D[继续]

超时时间：IDLE_TIMEOUT_MS（默认 10 分钟）。

回收流程

  1. 标记 disposed：防止后续操作
  2. 清理队列：清空输入队列
  3. 清理审批：清空 pending 审批
  4. 关闭子进程：stdin.end()
  5. 从 map 移除：agents.delete(instanceId)

崩溃恢复

检测崩溃

graph TD A[子进程 close 事件] --> B{disposed?} B -->|是| C[正常退出] B -->|否| D[崩溃] D --> E[标记实例] E --> F[重启子进程] F --> G[thread/resume]

恢复流程

  1. 检测崩溃：子进程 close 事件
  2. 标记实例：设置 process_exit 状态
  3. 清理状态：清空队列、审批、重试
  4. 重启子进程：spawnIfNeeded
  5. 恢复会话：thread/resume
