项目规范概述

codex-chat-mobile 有明确的开发与文档约定，确保代码质量和一致性。

TDD 约定

测试驱动开发

  • 先写测试：先写能表达预期的失败测试
  • 最小实现：做最小改动让测试通过
  • 真实验证：运行真实验证

四道门禁

graph LR A[代码变更] --> B[lint] B --> C[test] C --> D[protocol:check] D --> E[test:e2e] E --> F[提交]

代码规范

ESM

  • 模块系统：ESM（"type": "module"）
  • 导入：import
  • 导出：export

Node.js

  • 版本：≥ 20
  • 测试：node:test
  • 断言：node:assert

命名约定

类型 约定 示例
文件名 kebab-case agent-appserver.js
变量名 camelCase instanceId
常量名 UPPER_SNAKE_CASE BUFFER_CAP
类名 PascalCase CodexAppServerSession
函数名 camelCase handleNotification

文档规范

文档语言

  • 深度文档：中文
  • README：英文 + 中文镜像
  • CONTRIBUTING：英文

文档结构

文件 用途
README.md 英文项目概览
README.zh-CN.md 中文镜像
CONTRIBUTING.md 贡献流程
SECURITY.md 威胁模型
ROADMAP.md 路线图
docs/ 深度文档

文档守护

  • 契约测试：test/acceptance-doc.test.mjs
  • 结构调整：先改契约测试

Git 规范

提交信息

  • 格式：type(scope): description
  • 类型：feat、fix、docs、test、chore
  • 范围：可选

分支策略

  • 主分支：master
  • 功能分支：feat/xxx
  • 修复分支：fix/xxx

安全规范

不提交的内容

  • 本地状态
  • 密钥
  • 运行日志
  • Playwright 报告
  • .playwright-mcp/
  • data/

敏感信息

  • AUTH_TOKEN：不提交到代码库
  • VAPID 密钥：不提交到代码库
  • .env：.gitignore 排除

测试规范

Mock 优先

  • 日常开发：使用 mock server
  • 零 token：不调用真实 Codex CLI
  • 确定性：相同输入产生相同输出

真实冒烟

  • 边界：只在验证本地集成时
  • 工作区：一次性工作区
  • 审批策略：显式设置

协议规范

版本锁定

  • .codex-version：pin 住的 Codex CLI 版本
  • .protocol/stable/：pin 住的协议基线

协议检查

  • 覆盖检查：本项目用到的方法都还存在
  • 漂移检查：方法/类型/文件 hash 是否变化

PR 规范

提交前

  1. 运行四道门禁：npm run test:ci
  2. 检查协议：npm run protocol:check
  3. 更新文档：如果影响用户

PR 描述

  • 问题：解决什么问题
  • 方案：怎么解决
  • 测试：怎么验证

维护约定

文档维护

  • 同步更新：代码变更时同步更新文档
  • 中文优先：深度文档为中文
  • 英文镜像：README 保持同步

协议维护

  • 升级流程：见 PROTOCOL_UPGRADE.md
  • 漂移处理：先改代码，再更新基线
