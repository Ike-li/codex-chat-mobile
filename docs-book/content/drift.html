漂移清单概述

文档与代码不一致的地方，接手必读。以代码为准。

核心原则
代码是唯一可信的事实来源。文档会撒谎、会滞后、会自相矛盾；代码不会。当文档与代码冲突，永远以代码为准。

当前漂移点

截至手册编写时（v1.0），未发现明显漂移。项目文档与代码保持同步。

潜在漂移风险

协议版本

  • .codex-version：pin 住的版本（当前 0.142.5）
  • 风险：升级 Codex CLI 后可能漂移
  • 检查：npm run protocol:check

接口签名

  • docs/API.md：接口参考
  • 风险：代码变更后文档未同步
  • 检查：grep 源码确认

配置项

  • README.md：环境变量表格
  • 风险：新增/删除配置项后文档未同步
  • 检查：grep process.env

漂移检查方法

协议检查

命令
npm run protocol:check

检查两件事：

  1. 覆盖：本项目用到的方法都还存在
  2. 漂移：重新 generate-ts 后方法/类型/文件 hash 是否变化

接口检查

命令
grep -r "socket.on\|on(socket" server.js

检查 Socket.IO 事件是否与 docs/API.md 一致。

配置检查

命令
grep -r "process.env" server.js agent-appserver.js

检查环境变量是否与 README.md 一致。

如何报告漂移

如果发现文档与代码不一致：

  1. 确认：grep 源码确认
  2. 记录：添加到本页
  3. 修复：更新文档或代码
  4. 验证：npm run protocol:check

    5. 预防漂移

    契约测试

    • 文档契约：test/acceptance-doc.test.mjs
    • 协议检查：npm run protocol:check

    代码审查

    • PR 检查：代码变更时同步更新文档
    • 四道门禁：每次提交必须通过

    定期检查

    • CI：npm run test:ci
    • 协议：npm run protocol:check
