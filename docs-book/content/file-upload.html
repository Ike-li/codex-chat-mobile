文件上传概述

文件上传是 codex-chat-mobile 的安全功能：用户可以在手机上上传文件，Codex 会将其作为附件注入对话。

安全原则
不传输原始字节：文件以 owner-only 权限落盘，只把绝对路径注入协议帧
严格校验：类型、大小、数量限制
symlink 防御：防止符号链接攻击

上传流程

sequenceDiagram participant B as 浏览器 participant S as server.js participant FS as 文件系统 participant A as agent-appserver.js B->>S: user:message {attachments} S->>S: validateAttachments(attachments) S->>FS: saveAttachments(files) FS-->>S: 文件路径 S->>A: turn/start {input, attachments: [路径]} A->>A: 注入提示词

校验规则

类型校验

  • 允许的 MIME 类型：text/*、image/*、application/json 等
  • 拒绝的类型：可执行文件、脚本等

大小限制

  • 单文件：最大 10MB
  • 总大小：最大 50MB

数量限制

  • 单次上传：最多 10 个文件

安全落盘

owner-only 权限

graph LR A[上传文件] --> B[校验通过] B --> C[写入 uploads/] C --> D[设置权限 0o600] D --> E[返回路径]

代码位置：file-security.js 的 writeOwnerOnlyFile。

symlink 防御

防止符号链接攻击：

  1. 检查文件是否是符号链接
  2. 如果是，拒绝上传
  3. 记录审计日志

路径注入

文件落盘后，将绝对路径注入 turn/start：

注入方式
文件路径作为 turn/start 的 attachments 参数传入，app-server 会读取文件内容并注入对话上下文。

附件校验

validateAttachments

校验函数检查：

  • 格式：每项含 name、mimeType、dataBase64
  • 类型：MIME 类型在白名单内
  • 大小：Base64 解码后不超过限制
  • 数量：附件数量不超过限制

saveAttachments

保存函数：

  1. 创建 uploads/ 目录（如果不存在）
  2. 解码 Base64 数据
  3. 写入文件（owner-only 权限）
  4. 返回绝对路径

安全考虑

不传输原始字节

文件不通过 Socket.IO 传输原始字节：

  • Base64 编码：文件内容编码为 Base64
  • 落盘后注入：只把路径注入协议帧
  • app-server 读取：app-server 直接读取本地文件

权限隔离

  • owner-only：文件权限 0o600
  • uploads/ 目录：独立目录，便于管理
  • 审计日志：记录上传操作

错误处理

错误 处理
类型不允许 返回 400 错误
文件过大 返回 413 错误
数量超限 返回 400 错误
symlink 检测 拒绝上传，记录审计
写入失败 返回 500 错误
